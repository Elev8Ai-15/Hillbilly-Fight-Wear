## Landmines
- **Wrangler stamps the deploy with the commit of the current folder.** Run from elsewhere without `--commit-hash`, the dashboard shows another repo's hash (early 2026-10-08 deploys show `04f8f58`, a my-assistant commit). Claude Code's Bash resets cwd to my-assistant every call, so always pass `--commit-hash` there.
- **Local preview server goes stale** if `dist/` is deleted and rebuilt (its watcher dies). Restart the `hfw-site` preview (my-assistant `.claude/launch.json`, port 8789) and confirm with `curl -s localhost:8789/build | grep <new code>`.
- **`/images/*` is cached 30 days, `immutable`** (`public/_headers`). Replacing an image under the same URL does nothing for returning visitors. Bump `?v=N` on the path in `src/data/catalog.ts`.
- **Checkout is LIVE Stripe.** No checkout/session param changes without discussing with Brad first: `consent_collection[promotions]` took checkout down on 2026-08-13.
- On Windows, wrangler can print `Assertion failed ... async.c` on exit after a successful deploy. Trust `Deployment complete!` or the live check, not the exit text.
- Never borrow `CLOUDFLARE_API_TOKEN` from another repo's `.env`. If wrangler says "not authenticated", Brad runs `npx wrangler login`.
- White builder garments are generated by `scripts/whiten_garments.py` from the grey shots. Re-run the script; don't hand-edit `*-white-*.png`.
- The 3" HFW logo prints OUTSIDE on the back collar of every garment. Hoodie previews hide it (it sits under the hood). Order text says "Back Neck: HFW Logo (3")". That is correct.

## Real-request check (L4) for this repo
Creates live Stripe Checkout Sessions (no charge; nobody pays) and hits the gated and AI paths. Run in Bash:
```
P=https://hillbillyfightwear.com
# 1. Shop checkout, 2 tees (2-for-$50). Correct: JSON with "url":"https://checkout.stripe.com/...cs_live_..."
curl -s -X POST $P/api/shop-checkout -H 'content-type: application/json' -d '{"cart":[{"productId":"m3","title":"T-Shirt - HFW Classic","price":30,"image":"/images/products/web/m3-hfw-classic-front.webp","size":"L","color":"Black","style":"","qty":2,"type":"garment","garmentType":"tshirt"}]}' | grep -o 'cs_live_[A-Za-z0-9]\{8\}'
# 2. Builder checkout, hoodie + extra back graphic. Correct: a cs_live_ id
curl -s -X POST $P/api/create-checkout -H 'content-type: application/json' -d '{"garment":"hoodie","size":"L","color":"black","graphic":"human-cockfighter","placement":"full-front","additionalGraphics":[{"graphic":"thump-a-stranger","placement":"full-back"}]}' | grep -o 'cs_live_[A-Za-z0-9]\{8\}'
# 3. Owner-only endpoints stay locked. Correct: {"error":"Unauthorized"} [401] for both (never send the real password in a test)
for e in stripe/sync-catalog send-receipt; do curl -s -w ' [%{http_code}]\n' -X POST -H 'content-type: application/json' -d '{}' $P/api/$e; done
# 4. Merica. Correct: a plain-text reply quoting $65.00 for a hoodie + back graphic
curl -s -X POST $P/api/chat -H 'content-type: application/json' -d '{"messages":[{"role":"user","content":"Black pullover hoodie with a back graphic too, what does it cost?"}]}'
```
